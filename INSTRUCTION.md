## 2. Running locally

### Windows
1. Install Python 3.12+, Node.js 20+ and Docker Desktop (start Docker).
2. Double-click `Start App.bat`.
3. The browser opens http://localhost:5173. Create an account - you become the owner of a new workspace.

### macOS
1. Install Python 3.12+, Node.js 20+ and Docker Desktop.
2. In Terminal: `chmod +x "Start App (Mac).command"` (once), then double-click the file.

The launchers are safe to run repeatedly: they never delete files, never overwrite an existing `.env` and never reset the database. Stop the app by closing the server windows (Windows) or pressing Ctrl+C (macOS). PostgreSQL keeps running in Docker (`docker compose stop db` to stop it); data persists in the `feedbackmind-pgdata` volume.

Local URLs: app http://localhost:5173 · API http://127.0.0.1:8000 · docs http://127.0.0.1:8000/api/docs.

## 3. First steps in the app

1. **Overview → Load sample dataset** to explore with 240 synthetic, clearly labelled records (remove them later with *Remove demo data*), or
2. **Imports** → upload a CSV/XLSX/JSON file (try `sample-data/sample-feedback.csv`), map columns, preview, validate and confirm.
3. **Topics** → review default keyword rules, add your own topics, use *Find suggestions*.
4. **Insights → Generate insights**; **Alerts → New rule**; **Reports → Generate**.
5. **Settings → Members** to invite colleagues (copy the one-time link), **Settings → AI provider** to enable AI.

## 4. Configuration

All settings are environment variables (local: `.env` in the repository root; production: the hosting dashboard). See `.env.example` for comments and defaults.

### Production environment checklist

| Variable | Required | Secret | Purpose | Where to obtain |
| --- | --- | --- | --- | --- |
| `ENVIRONMENT` | yes | no | `production` enables strict checks (secret length, no SQLite, no wildcard CORS) and HSTS | set to `production` |
| `DATABASE_URL` | yes | yes | PostgreSQL connection | Render database "Internal Database URL" (wired automatically by the Blueprint) |
| `SECRET_KEY` | yes | yes | JWT signing (≥ 32 chars) | generated by Render (`generateValue`) or `python -c "import secrets;print(secrets.token_urlsafe(48))"` |
| `ENCRYPTION_KEY` | recommended | yes | Encrypts webhook secrets and workspace AI keys | generated by Render, or `python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"` |
| `CORS_ORIGINS` | yes | no | Frontend origin(s), comma-separated | the frontend URL |
| `FRONTEND_URL` | yes | no | Base for invitation links | the frontend URL |
| `TRUSTED_PROXY_HEADERS` | on Render | no | Use the platform's `X-Forwarded-For` for rate limiting | `true` behind Render's proxy |
| `EMBEDDED_WORKER` | no | no | Run background jobs inside the API (`true`) or in a separate worker (`false`) | `true` on a single free instance |
| `WORKER_CONCURRENCY` | no | no | Worker threads | `1` |
| `AI_PROVIDER` | no | no | `none`, `anthropic`, `openai`, `gemini` | your choice |
| `AI_MODEL` | no | no | Model name (default for Anthropic: `claude-opus-5-5`) | provider documentation |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` | only with that provider | yes | Provider credentials | provider console |
| `AI_DAILY_TOKEN_LIMIT` | no | no | Per-workspace 24 h token budget (0 = unlimited) | default 2,000,000 |
| `MAX_IMPORT_MB`, `MAX_IMPORT_ROWS` | no | no | Import limits | defaults 20 / 100000 |
| `DOCS_ENABLED` | no | no | Serve `/api/docs` | `true` or `false` |
| `REGISTRATION_ENABLED` | no | no | Allow public sign-up (invitations always work) | `true` / `false` |
| `ACCESS_TOKEN_EXPIRE_MINUTES`, `REFRESH_TOKEN_EXPIRE_DAYS` | no | no | Session lifetimes | defaults 15 / 14 |
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` | no | no | Connection pool | small values on free databases |
| `VITE_API_URL` | frontend build | no (public) | Backend URL compiled into the frontend | the backend URL |

Never put secrets in `VITE_*` variables - they are public in the browser bundle. Never commit `.env`.

Not used by this project (and therefore not required): Redis, S3 / object storage. Uploads and reports are stored in PostgreSQL.

## 5. Deploying on Render

The repository contains a Blueprint (`render.yaml`):

| Service | Type | Notes |
| --- | --- | --- |
| `feedbackmind-ai-db` | PostgreSQL (free) | Application data, import files until processed, generated reports. Free databases expire after 30 days unless upgraded. |
| `feedbackmind-ai-api` | Web service (Python, free) | `alembic upgrade head && uvicorn ...`; health check `/health/ready`; embedded job worker |
| `feedbackmind-ai-frontend` | Static site (free) | `npm ci && npm run build`, publishes `dist`, SPA rewrite to `/index.html` |

Steps:
1. Render Dashboard → **New → Blueprint** → connect GitHub repository `OlehDatsyk/feedbackmind-ai` → branch `main`.
2. Review the resources and click **Apply**. Render creates the database first, then the API (migrations run on start) and the frontend.
3. Optional AI: in `feedbackmind-ai-api` → Environment, set `AI_PROVIDER` and the matching API key, then redeploy.
4. Verify: `<api>/health/ready` returns `{"status":"ok","database":"ok"}`; open the frontend, register, load sample data.

If you rename services, update `CORS_ORIGINS`, `FRONTEND_URL` (API) and `VITE_API_URL` (frontend) to the new URLs and redeploy both.

Background work: free web services sleep after ~15 minutes without traffic. Jobs are stored in PostgreSQL and continue when the service wakes. For continuous processing use a paid instance, or set `EMBEDDED_WORKER=false` and add the worker service shown in `render.yaml`'s comments.

Never reset or delete the production database. Migrations are additive.

## 6. Administration

- **Roles:** Viewer (read, download reports, AI analyst), Analyst (+ add/import/analyse, topics, insights, alerts, reports), Administrator (+ delete records, members, integrations, AI settings), Owner (+ delete workspace, manage owners). A workspace always keeps at least one owner.
- **Invitations:** Settings → Members → Create invitation → share the one-time link (valid 7 days).
- **AI costs:** AI runs only when started by a user; limit with `AI_MAX_RECORDS_PER_RUN`, `AI_BATCH_SIZE` and `AI_DAILY_TOKEN_LIMIT`. Usage per 24 h is shown in Settings → AI provider.
- **Integrations:** Integrations → New connection → REST API key or signed webhook. Secrets are shown once; rotate them from the same page.
- **Backups:** use your database provider's backups (Render: paid plans include point-in-time recovery).

## 7. Troubleshooting

| Symptom | Fix |
| --- | --- |
| "Cannot reach the FeedbackMind API" | Backend not running, or `VITE_API_URL` / `CORS_ORIGINS` mismatch |
| `/health/ready` returns 503 | Database unreachable or migrations not applied (`alembic upgrade head`) |
| Import rows rejected as "ambiguous date" | Choose *Day first* or *Month first* in the import options |
| Characters look wrong in the import preview | Re-upload with an explicit encoding |
| AI buttons disabled / "AI is not configured" | Set a provider and key (server or workspace) |
| Webhook creation fails | Configure `ENCRYPTION_KEY` |
| Production start fails with a settings error | `SECRET_KEY` too short, SQLite URL or wildcard CORS in production |
