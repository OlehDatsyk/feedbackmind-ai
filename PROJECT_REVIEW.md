| 1 | High | CSV rows with more fields than the header (unquoted commas) were silently reshaped by the pandas parser, which treated the first column as an index - feedback text was lost without any error | Replaced with the standard `csv` module; such rows are rejected with an explanatory reason and appear in the rejected-rows report (test added) |

| 5 | Medium | Short non-UTF-8 CSV files were decoded with the wrong code page by statistical detection | Predictable order UTF-8 → Windows-1252 → detection, encoding reported back, explicit encoding option in the wizard |
| 6 | Medium | Oversized uploads were fully received before rejection | `Content-Length` checked in middleware before the body is read; size also enforced while reading |
| 7 | Medium | Unit-of-work could insert analysis rows before their feedback row (FK violation) during bulk creation | Explicit relationships so inserts are ordered |
| 8 | Medium | AI usage was recorded in a second connection, which deadlocks on SQLite and could lose the record on rollback | Recorded in the caller's transaction (callers commit on success and on handled errors) |
| 9 | Low | One-word texts ("ok") were classified by the lexicon | Texts with fewer than 3 words are *uncertain* in the rule-based analyser |
| 10 | Low | Default keyword "fast" assigned "fast delivery" to Performance | Removed from the default Performance rules (affects new workspaces; existing topics are editable) |
| 11 | Low | Horizontal overflow at 375 px (dashboard grid, alert evidence links) | Explicit single-column grids, shrinkable cards, wrapping link lists |
| 12 | Low | Ambiguous joins in insight evidence queries | Explicit `select_from` |

## 4. Data integrity

- Original text is stored verbatim; analysis never modifies it. Edits are logged, and earlier analyses stay in the history.
- Manual corrections append a `manual` analysis with the previous label and the corrector; AI and lexicon results are preserved.
- Imports: every row ends up imported, rejected (invalid) or reported as a duplicate - counts add up to the file's rows (tested). Valid rows are inserted in one transaction; a failure leaves no partial data. The raw file is cleared after processing; rejected rows are kept.
- Duplicate key: normalised text + product + UTC day + customer reference (plus external IDs). Two different customers writing the same short text on the same day are not merged.
- Dates: ISO and Excel dates parsed directly; naive times use the workspace time zone; ambiguous day/month values are rejected unless the order is chosen or inferred from unambiguous rows; dates before 1990 or in the future are rejected.
- Archive excludes records from analytics but keeps them; delete is permanent (admins only, with confirmation).
- AI results are matched by record ID; IDs not sent to the model are ignored.

## 5. Analytics accuracy

Verified with controlled datasets (`tests/test_analytics.py`): percentages use classified records as denominator (3/7 = 42.9 %, not 3/10); averages exclude records without a score; archived records excluded; empty datasets return `null`, not 0 %; inclusive date filters at time-zone boundaries (Asia/Tokyo); empty buckets kept; small buckets flagged; topic aspect sentiment falls back to record sentiment; two-proportion z-test matches a hand-computed reference (z = 3.5355, p ≈ 0.0004). Charts and summary cards use the same filter function and the same rows.

## 6. Security

See `SECURITY.md` for the full model. Tested: password policy, login enumeration resistance, refresh rotation and reuse detection, logout, password change revoking tokens, cross-workspace ID tampering (read/update/delete/notes/corrections/bulk/imports/reports/conversations), header forgery, foreign references, role enforcement, CORS allow-list, security headers, LIKE wildcard escaping, stored XSS rendered as text, formula injection in exports, upload type/size/macro checks, webhook signature/replay, hashed API keys and encrypted secrets never returned.

Secret scan: no real secrets in the repository; `.env` is git-ignored; test keys are obvious placeholders.

## 7. AI validation

Mock-provider tests confirm: AI analysis only uses provided records; invented quotes are removed; invented record IDs are ignored or stripped from answers; date range and sample size come from deterministic queries; workspace data never reaches prompts for another workspace; invalid structured output is retried once, then the records are marked failed; token usage is recorded; not-configured state is explicit everywhere. Live provider calls were not made.

## 8. Remaining limitations

- Rule-based sentiment is English-only and lexicon-based.
- External review-platform connectors are not implemented (documented with requirements).
- No e-mail delivery; invitation links are shared manually.
- Rate limiter and embedded worker are per process (single-instance design; a separate worker process is supported).
- Analytics aggregate in memory; suitable up to roughly 100k records per query.
- The macOS launcher and live AI providers were not exercised.
- Screenshots in the README are placeholders.
